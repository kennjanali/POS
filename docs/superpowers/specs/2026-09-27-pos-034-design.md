# POS-034 — Product & Platform Design

Status: **approved in brainstorming 2026-09-27, awaiting written-spec review.** Nothing implemented.
Supersedes the product direction in `REWORK-PLAN.md` (restaurant-only, 2% fee) and `PROJECT-BRIEF.md`.
Those files stay as history; implementation follows this spec.

Marketing lives in its own document, parked until launch: `2026-09-27-pos-034-marketing-plan.md`.

---

## 1. Goal

Evolve the existing POS@034 build into **POS-034**: a simple, offline-first point of sale with
inventory, orders/sales and printed slips. It works for many kinds of small shops (restaurants,
hardware stores, auto parts and service, car washes and more) through **presets**, not separate apps.
The vendor installs it on an Android tablet.

POS-034 is the first app sold under **kennali.com**, a shop of simple business apps. The platform
behind it (accounts, licensing, backups, updates, vendor dashboard) is shared by future apps.

### Success criteria
- One app, one code base, one license type serves every preset.
- Selling, stock, credit, quotes, reports and daily close all work with no internet.
- Stock can never go below zero, anywhere.
- No closed sale, payment or stock movement is ever lost or half-saved (crash, force-kill, flat battery).
- A replacement tablet is fully restored from the encrypted cloud backup with the license key + recovery code.
- A prospect can try "their" kind of shop in the web demo in under a minute.

### Decisions (fixed)

| # | Decision |
|---|---|
| 1 | **Evolve this repo.** No rewrite. Keep the offline engine, users/roles, void-never-delete, audit, tax engine, license, backups, printing, daily close |
| 2 | **One app with shop-type presets** (bundles of feature switches) |
| 3 | **Pricing: one-time license per tablet + optional yearly maintenance** (updates + support). No sales-percentage fee, no subscription |
| 4 | **Android tablet only** for v1, Bluetooth thermal printer |
| 5 | **Not a BIR-registered POS.** Prints order slips marked "Not an official receipt" |
| 6 | Name **POS-034**, slug `pos034`, Android app ID `com.kennali.pos034` |
| 7 | Domains: `kennali.com` brand + shared platform, `pos-034.kennali.com` product site + demo |
| 8 | **Negative stock is never allowed** |
| 9 | Storage: one on-device database file, one table per record type, each row stored as JSON; JSON files for export and backup |

## 3. Presets (shop types)

A preset is **only a set of default switch values**. There are no per-preset code paths; every
behaviour is gated by a switch. The owner can change any switch later in Settings.

| Switch | Restaurant / Food | Retail / Hardware | Auto Parts & Service | Car Wash / Service | General |
|---|---|---|---|---|---|
| `openOrders` (tables / jobs / queue) | on (label "Table") | off | on (label "Job") | on (label "Queue") | owner picks |
| `serveStep` | on | off | off | off | owner picks |
| `services` | off | on | on | on | owner picks |
| `quotes` | off | on | on | off | owner picks |
| `credit` | off | on | on | off | owner picks |
| `vehiclePlate` | off | off | on | on | owner picks |
| `measuredUnits` (decimal qty) | off | on | off | off | owner picks |
| `statutoryDiscount` (senior/PWD) | on | off | off | off | owner picks |

- Order types per preset: Restaurant = dine-in, takeout, delivery; others = walk-in, pickup, delivery.
- A new business type later = a new preset + a sample catalog. No new code paths.
- **Statutory discount:** on by default only for restaurants. RA 9994 / RA 10754 grant the 20% +
  VAT exemption on specific goods and services (restaurants among them), not on general hardware
  or tires. The owner can switch it on. Confirm the exact coverage with a tax practitioner before
  launch (§12).

## 4. Data model

All IDs are UUIDv7. All money is integer centavos. Records marked *append-only* are corrected
by voiding, never by editing or deleting.

**Settings** (changed): business profile (name, address, contact number), VAT registered, prices
include VAT, `shopType`, the feature switches (§3), default reorder level, default quote validity
(days, default 7), receipt footer, paired printer, practice-mode flag.

**Product** (changed)
- `kind`: `stock` | `service`
- `sku` (optional, unique when present), `category`
- `unit`: pcs, set, m, kg, box, hour, serving, etc.
- `priceCents`, `costCents`, `vatExempt`, `active`
- `openPrice` (services only): price typed at sale
- `reorderLevel` (stock only; falls back to the shop default)

**Quantities:** up to 3 decimals when `measuredUnits` is on and the unit is measured; otherwise
whole numbers. Stored as integer **thousandths** (2.5 m → 2500) so quantity maths never uses
floating point. Line total = round-half-up(unit price × qty) to the centavo.

**Customer** (new): name, phone, note, active. **The balance is never stored.** It is always derived (below).

**Sale** (the current Order, changed; append-only once closed)
- Existing fields keep their meaning: number, status (open / closed / voided), lines, tenders,
  discount, frozen totals, frozen line cost, actor fields, void fields.
- New: `customerId` (optional; required when any tender is `account`), `vehiclePlate` (optional),
  `fromQuoteId` (optional).
- Lines reference stock or service products. The restaurant-only fields (diners, eligible diners,
  serve state) are used only when the `serveStep` / `statutoryDiscount` switches are on.
- New tender method: `account` ("Charge to account"). It can cover all or part of a sale.

**Quotation** (new)
- Own gapless number sequence `Q-0001`, separate from sale numbers.
- `customerId` (optional), lines, discount, totals, `validUntil`, status: open / converted /
  expired / cancelled, `convertedSaleId`.
- Never affects stock or sales totals.

**Credit payment** (new, append-only): customer, amount, method (cash / GCash / Maya / card /
bank / other), reference no., time, actor, void fields.

**Customer balance** = Σ `account` tenders on closed sales − Σ non-voided credit payments. Voided
sales drop out automatically, since only closed sales count.

**Stock move** (unchanged shape): reason ∈ sale, void, restock, spoilage, count, opening; plus
optional `supplier` / `docNo` text on restocks and an optional new unit cost.

**Stock hold** (derived, not stored): Σ qty of stock lines on **open** sales. Available = on hand − held.

**Daily close** (changed, see §7), **User**, **Audit entry**, **Branch** (one per install):
unchanged except as noted.

### Storage
- One database file on the tablet; one table per record type: settings (kv), products, customers,
  sales, quotes, creditPayments, stockMoves, closes, audit. Each row is stored as JSON under its ID.
- **Atomic multi-table writes (new):** closing a sale writes the sale, its stock moves and the
  audit entry in **one transaction**. Voids, credit payments, receipts of stock and quote
  conversions do the same. Today each table is written separately, which lets a crash leave a
  sale without its stock moves.
- Web demo keeps browser storage behind the same interface.
- Autosave on every change, as today. A failed write is always shown in the top bar.

## 5. Stock rules

**Rule: available stock may never go below zero.** Enforced in the business core, not only in the UI.

| Point | Rule |
|---|---|
| Add to cart / open order | Can't exceed available (on hand − held). The tile shows "Only N left"; 0 = greyed "Out of stock" |
| Open sales (tables, jobs, queue) | Stock lines **hold** their quantity while the sale is open. Removing a line or cancelling the sale releases it |
| Close / serve | Rechecked inside the same transaction as the deduction. If short, nothing is written and the screen names the short line |
| Quote → sale | Quantities checked; short lines must be reduced or removed before converting |
| Spoilage / damage | Can't exceed on hand |
| Stock count | Records the counted quantity (≥ 0) and writes the difference as a move |
| Void | Returns stock (only ever increases it) |
| Service items | Never touch stock |

- A shelf/system mismatch is fixed only by a **stock count or a receipt** (owner or stock clerk), logged with who and why. There is no override at the counter.
- **Migration:** existing negative balances (from practice data) are reset by a logged opening count when the new build first runs. Practice data is otherwise wiped at go-live anyway.

**Low stock**
- Tile badge "low" when available ≤ reorder level.
- A notification to the owner and stock clerk when a sale or move takes a product to or below its reorder level.
- A Low stock / Out of stock list on the Dashboard and the Stock screen, most urgent first, with a Receive stock shortcut.

**Receive stock:** pick products, quantity each, optional new unit cost, optional supplier and
document number. A new cost applies to **future** sales only; past sales keep their frozen cost.

## 6. Flows

### 6.1 Sell (all presets)
Product grid (category tabs + search by name/SKU) and a cart. Tap to add; measured units open a
qty pad. Open-price services ask for the amount. Discount: statutory (if on) or custom % / fixed ₱.
Pay: split tenders plus `account`. Complete = number assigned, totals frozen, stock deducted, slip
printed, all in one transaction.

- **Retail:** quick sale: cart → pay → next. No open orders.
- **Open-orders presets:** open a table/job/queue ticket (customer and plate optional). Several open
  side by side; stock is held while open; deducted at pay (Auto, Car Wash) or at serve (Restaurant).
- **Void:** owner only, reason required. Stock returned; any `account` amount leaves the customer's balance.

### 6.2 Quotations
Save the cart as a quote → `Q-` number, valid for the default number of days. Print it on the
receipt printer marked **"QUOTATION — not a receipt"**, or share it as an image. Convert → retail
goes to payment; open-orders presets create an open ticket. Quoted prices are honoured.
Converting an expired quote warns first. "Re-quote" copies it at current prices.

### 6.3 Credit (utang)
Customers list (balance, last payment, age of oldest unpaid charge; sort by amount owed); customer
detail timeline with a running balance; Receive payment (amount, method, reference) prints a
payment slip with the new balance. Payments reduce the overall balance, not a specific sale. Void
a payment: owner only, reason required. No credit limits, no interest in v1.

### 6.4 Setup wizard
1. Shop type (sets the switches)
2. Business name, address, contact number, VAT registered, prices include VAT
3. Owner name + PIN ×2
4. Products: sample catalog for the preset / import CSV / start empty
5. Pair printer + test print
6. Recovery code shown once, printed
7. Activate license, or start in practice mode

The existing "restore from cloud backup" path stays available on the first screen.

### 6.5 CSV import / export
Template columns: `name, sku, category, kind, unit, price, cost, reorder_level, opening_qty`.
A preview comes before any write ("312 rows, 3 errors: row 14 price missing"). Rows with errors
are fixed or skipped. Matching SKU = update, never a duplicate. Opening qty is written as `opening`
moves. Export uses the same format.

## 7. Daily sales and daily close

Dashboard and close show two blocks:

- **Sales:** count, gross, discounts, net sales, of which on account, voids (count + amount).
- **Money collected:** by method from sales paid that day, plus credit payments received that day
  by method, giving the total collected.
- **Expected cash in drawer** = cash from sales + cash credit payments; optional counted cash and the difference.

The daily close (auto at 23:59 or next launch; manual + printable) freezes both blocks. Windows,
the carrying forward of voids, and the hash chain all work as today. The close record gains
`onAccountCents`, `creditCollected` (by method) and `expectedCashCents`, and these are in the hash.
Each close also stores a `format` number, and the hash covers the fields of its own format, so
closes written by the current build still verify after the upgrade.

Dashboard extras: today and month net, best sellers, gross profit (frozen cost), total utang
outstanding, low-stock list.

## 9. Practice mode and demo

- Practice mode as today: watermarked, holds fake data, one-way switch to live (needs a license).
- **Load demo business:** Restaurant, Hardware Store, Auto Parts & Service, or Car Wash. Each loads
  its preset plus a sample catalog, a few weeks of sales, customers with balances, open quotes and
  tickets, and some low-stock items. Switching replaces the practice data.
- The web demo at `pos-034.kennali.com/demo` has the same switcher and is always in practice mode.
- Demo data must respect every rule in this spec (no negative stock, balanced credit, a valid close chain).

## 10. Platform (kennali.com)

| Address | Purpose |
|---|---|
| `kennali.com` | Brand home; product cards (POS-034 first) |
| `pos-034.kennali.com` | Product site: features, industry pages, pricing, FAQ |
| `pos-034.kennali.com/demo` | Web demo |
| `kennali.com/account` | Customer accounts shared by all apps: licenses, downloads, backup status |
| `api.kennali.com` | Device endpoints shared by all apps: activate, heartbeat, backups, updates |
| `kennali.com/admin` | Vendor dashboard, password-protected |

Evolved from `license-server/`:
- **License** payload gains `app: "pos-034"`. Otherwise the same: activate once online, signed,
  verified offline every launch, one tablet per license, released by the vendor to move it,
  `updatesUntil` = maintenance end. An expired or missing license never blocks existing data.
- **Purchase:** manual GCash / bank transfer. The vendor approves on the dashboard, and the key appears in the customer's account.
- **Heartbeat: health only:** app, version, tablet model, OS, last successful backup, printer OK,
  error flag. **No sales figures.** Removed: the `closes` payload, the fee/billing tables and the fee UI.
- **Dashboard "My Customers":** business, city, app, shop type, version (+ how many behind),
  license and maintenance expiry, last backup (green / amber / red), last seen. Actions: create /
  approve, release tablet, revoke, extend maintenance, record a license payment, notes.
- **Encrypted backups:** unchanged (sealed on the tablet with the recovery-code key; last 3 days + first of each month).
- **Updates** (new, not built): web-layer updates applied only with no open sales or after the
  daily close, a backup taken first, automatic rollback if the new version fails to start,
  available only while maintenance is active; beta channel on the pilot shop first. Full APK
  updates come from the customer's account or are installed on-site.

## 12. Testing and launch gates

**Automated checks** (extend `npm run check`):
- Tax: the existing cases, plus statutory-discount-off presets.
- Decimal quantities: 2.5 m × ₱38.40 = ₱96.00, and rounding at the half-centavo.
- Stock: can't sell beyond available; holds across two open tickets; recheck on close; count/spoilage can't go below 0; a void restores.
- Atomicity: a simulated failure mid-close leaves neither the sale nor its moves.
- Credit: charge, part-pay, void sale, void payment. The balance is right at every step.
- Quotes: numbering gapless and separate; convert honours prices; a short-stock convert is blocked.
- Daily close: sales vs collected, credit collected, expected cash, chain intact / tamper detected.
- CSV: preview errors, SKU update, no duplicates, opening moves.
- License (with `app`), backups (seal/open, wrong code), the existing auth checks.
- Server: activation, second-tablet refusal, heartbeat without sales data, backup round trip.
- Migration: a current-build backup loads into the new build (products get `kind: stock`, roles unchanged).

**On a real tablet + printer** (before any customer):
- Opens in airplane mode.
- Kill the app mid-sale 20× → nothing lost or half-saved.
- Reboot → intact.
- Printer off/on reconnects.
- Slips print correctly at 58 mm and 80 mm.
- Restore onto a factory-reset tablet.
- Each demo business loads and sells.

**Before launch** (non-code):
- Tax practitioner confirms the statutory-discount coverage and the "not an official receipt" slip wording.
- EULA + privacy notice (Data Privacy Act, RA 10173).
- Vendor's own business registration and receipts for license sales.

multi-branch; cloud sync; owner phone dashboard; Windows / iPad; payment gateway; offline QR
