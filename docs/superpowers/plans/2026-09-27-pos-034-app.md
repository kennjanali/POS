# POS-034 App (Plan A) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Evolve the POS@034 app into POS-034: a preset-driven, offline POS for many shop types, with owner-only inventory, prices and discounts, promo codes, quotations, no negative stock, and atomic saves.

**Architecture:** All business rules stay in the zustand store (`src/store/usePos.ts`) and pure modules in `src/lib/`. Screens only call store actions. Presets are data (`src/lib/presets.ts`); every behaviour is gated by a feature switch, never by shop type. Every permission goes through `can()`, and store actions re-check it. Persistence becomes one atomic batch per state change (blob plus all changed rows).

**Tech Stack:** Next.js 15 static export, React 19, TypeScript, zustand 5, Tailwind 4, Capacitor 8 (Android, SQLite), IndexedDB (web demo). New dev dependencies: Vitest and fake-indexeddb.

**Spec:** `docs/superpowers/specs/2026-09-27-pos-034-design.md`

**Not in this plan:**
- **Plan B** (kennali.com platform): server `app` field, health-only heartbeat on the server side, dashboard simplification, domains, `LICENSE_SERVER_URL` → `api.kennali.com`.
- **Plan C:** the updates pipeline.

The app keeps talking to the current server URL until Plan B ships.

## Global Constraints

- Money is integer centavos (`Centavos`, `src/lib/money.ts`), everywhere.
- Quantities are integer **thousandths** (`Qty`, `src/lib/qty.ts`); 2.5 m = `2500`. No float quantity maths anywhere.
- Frozen, never renamed:
  - IndexedDB / SQLite database name `pos034`;
  - persist key `pos034-v7` (the key stays; only `version` goes to 8);
  - row store names `orders`, `stockMoves`, `closes`;
  - localStorage keys `pos034.*`.
- Product name `POS-034`. Slug `pos034`. Android app ID and namespace `com.kennali.pos034`.
- **No credit / utang anywhere.** A sale closes only when payments equal the total.
- **No Senior/PWD discount** anywhere: no code, no copy.
- **Available stock never goes below zero.** Enforced in the store, not only in the UI.
- Roles: `superadmin` (label "Owner") and `staff` (label "Staff"). Every access decision goes through `can()` in `src/lib/permissions.ts`, and store actions that change money, stock, prices or settings re-check it.
- Owner-only:
  - Inventory (products, services, stock, promo codes, import/export);
  - price edits;
  - manual discounts;
  - cancelling sales or quotes;
  - reports, settings, users.
- Staff may:
  - take orders;
  - take payment;
  - make, print and convert quotes;
  - apply a promo code;
  - see Today's sales.
- Every item sold exists in Inventory; there are no typed prices or one-off lines at the counter.
- One discount per sale: none, a promo code, or an owner discount (% or fixed ₱). Never stacked.
- Plain words on screen:
  - "Sale", "Add stock", "Today", "Practice mode", "Payment";
  - "Cancel sale" (not "void");
  - "Today's summary" (not "daily close").
- Fixed copy:
  - the slip footer keeps "THIS IS NOT AN OFFICIAL RECEIPT OR INVOICE";
  - quotes print "QUOTATION — not a receipt";
  - the practice watermark reads "*** PRACTICE MODE ***".
- `npm run check` passes at the end of every task. From Task 3 it includes `npm test` (Vitest).
- Per-product `vatExempt` is stored but the tax engine ignores it today. This plan does not change that (the spec gap is noted for the user).

## Review Focus

1. **Price changed while an item sits on an open ticket.** The line keeps the price it was added at; the new price applies to new lines. Tested in Task 9.
2. **Decimal quantity typed badly** ("2,5", "0.0004", "-1", "1.2345", or "1.5" on a whole-number unit). It is refused with a message; nothing is added. Tested in Task 8.
3. **Promo code typed with spaces or lower case** (" grand10 ") matches `GRAND10`; a code whose `endsOn` is today still works until midnight (Manila business date). Tested in Task 12.
4. **A product deactivated after it was quoted, or while on an open ticket.** It can't be added to new sales. Converting a quote that contains it is refused with the line named. An open ticket that already holds it can still be paid. Tested in Tasks 9 and 13.
5. **A spreadsheet from Excel or Google Sheets:**
   - UTF-8 BOM, CRLF line endings;
   - quoted names containing commas or `""`;
   - trailing blank lines.
   It imports correctly. Tested in Task 16.

**Interfaces:**
- Produces, in `storage.ts`:
  - `ROWS` adds `products`, `audit`, `promos`, `quotes`. The existing three names are unchanged.
  - `interface WriteBatch { kv: { name: string; value: string }[]; rows: { store: RowStore; changed: { id: string }[]; removed: string[] }[] }`
  - `StorageBackend.writeBatch(batch: WriteBatch): Promise<void>`: one transaction, all or nothing. It replaces `writeRows`.
  - `writeBatch(batch)` is exported (reported through `onPersistWrite`, like today).
  - `setStorageBackend(b: StorageBackend | null): void` (tests only; when set, `canStore()` is true).
  - `blobStorage`: the persist storage. `getItem` reads the kv value; `setItem` does **not** write. It keeps `value` as the pending blob, read by `takePendingBlob(): { name: string; value: string } | null`.
- Produces, in `usePos.ts`: the subscriber no longer writes directly. It schedules `flush()` with `queueMicrotask`, at most once per tick.
  - `flush` diffs every row store (orders, stockMoves, closes, products, audit, promos, quotes), takes the pending blob, and calls `writeBatch` once.
  - `products` and `audit` leave `partialize` and are loaded in `loadRows`. When loaded rows are empty, the blob's legacy arrays are adopted and written (the same pattern as today's orders migration).
