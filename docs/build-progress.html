Task 14 in detail

Today, This month, and Today’s summary. Committed as Today home screen, This month for the owner, and a richer Today's summary.

Done and passing

  • / is Today for everyone; the counter moved to /sell and the report to /month. Both roles land on Today, so nobody signs in to a screen they cannot use
  • Today shows the day’s net, sales count, and what was collected by method — a sale belongs to the day it was paid and a cancellation to the day it was cancelled, so a void never erases a day it did not happen on
  • The owner also gets the low-stock list, and This month adds gross profit on frozen cost, best sellers, the promo/owner discount split, promo-code use, and VAT for a registered shop
  • Close format 2 carries the discount split, VAT, the cash the till should hold, and what the owner counted. The slip then shows over or short, so a shortage needs no arithmetic on paper
  • A close already on the till still verifies: a format-1 close hashes over exactly the fields it had, so no day reads as tampered with. Editing expectedCashCents is caught
  • A legacy discount is in neither the promo nor the owner bucket, rather than in the wrong one

Decisions and still to do

  • The plan asks This month to show promoUses, which counts every sale that ever used a code. Under a “Today” or “Last 7 days” filter that number is not about the period on screen, so the codes are counted over the same rows as every other tile. promoUses stays the all-time count it already was.
  • The counted-cash box is left blank by default: the nightly close is taken by the app and has no count to record. It is not given an “expected” figure to compare against, because the close covers the window since the last close, not the calendar day
  • QuoteLine.unit was carried in the counter move untouched
  • Manual pass at 1280×800: sign in as staff and confirm Today has no low-stock list and no This month link, then ring up a sale and close the day with a count. All eight routes serve; the new screens have no component test — the project has no component harness

  • Each shop type gets its own 10–15 item catalog — the carinderia menu, a hardware shelf that sells by the metre and the kilogram, tires and mags and labour by the hour, and wash and wax sizes. General starts from the retail shelf

Task 16 in detail

Spreadsheet (CSV) import and export. Committed as Import and export Inventory as a spreadsheet, with a preview before writing.

Done and passing

  • The stock list goes in as a spreadsheet and comes back out as one. Nine columns: name, sku, category, kind, unit, price, cost, reorder_level, opening_qty — and a “Download template” that is the same nine with the rows empty
  • Real CSV, not a spreadsheet app’s idea of one: quotes around anything holding a comma, a quote or a line break, doubled quotes inside those, CRLF endings, a UTF-8 BOM taken off the front, CRLF or bare LF accepted on the way in, and the blank line at the end of the file ignored
  • Nothing is written until the owner has read what the file will do: 312 rows ready (4 added, 308 updated), then every row it could not read named by line number — Row 14 — Price is missing. — with an “Import the good rows” button. One typo does not void the other three hundred
  • A row whose SKU is already on the shelf updates that item — price, cost, category, unit, reorder level — and never creates a second one with the same name
  • An item’s opening quantity is booked as an opening stock move, so the first number on the ledger is a real one and the stock history says where it came from
  • A matched item’s opening_qty is ignored: it has been counted already, and a second import of the same file would otherwise double the shelf
  • One write, one log line. A 300-row file is one act by the owner, and a half-applied import — some prices changed, some items doubled — is worse than none at all
  • Export writes pos034-products-YYYY-MM-DD.csv with today’s on-hand count in the last column, so export → edit prices → import works as a round trip

Decisions and still to do

  • A match updates the five fields the plan lists and nothing else. Name, SKU and kind are what the sales history and the stock ledger are filed under, and quietly turning a stocked item into a service would strand its stock
  • Columns are matched by name in any order rather than by position. An owner who drags them round in Excel gets a working import instead of an error about the first line
  • A price with no digits in it is refused as Price is not a number. The money parser reads “₱1,250.50” happily and turns ask me into zero — and a shelf of a hundred items priced at zero is not a shrug
  • Quantities are checked against the same decimal rule as everywhere else: 2.5 m is fine, 2.5 pcs is an error, and a shop that has not turned on selling by measure refuses the decimal outright
  • A service row has no reorder level and no opening quantity, and writes no stock move. A service is never on a shelf
  • The whole import is one inventory.manage action behind a preview. Manual pass still open: export → open it in a spreadsheet → edit a price → import, on a real tablet

What the redesign changed

The 2026-09-27 spec supersedes the product direction in REWORK-PLAN.md (restaurant-only, 2% fee) and PROJECT-BRIEF.md. Those files stay as history.

  • Dropped: the 2% technology fee and all server-side billing; the Senior/PWD statutory discount; multi-branch.
  • Added: shop-type presets (restaurant, hardware, auto, car wash, general) as feature switches; promo codes; quotations; product kind / SKU / category; decimal quantities.
  • Kept: the offline engine, void-never-delete, the audit trail, PINs and the recovery code, the permission matrix, licensing, backups, printing, the daily close.
  • New rules: stock can never go below zero; one discount per sale and it comes from the owner; no price is ever typed at the counter; every sale is paid in full — no credit.
